# Финальное задание Agents Week

## Что нужно было сделать

Финальное задание посвящено разработке LLM-агентов для небольшого интернет-магазина электроники. В шаблоне уже были заданы каталог товаров, инструменты магазина, состояние сессии, трейсинг вызовов инструментов и открытые проверки. Решение нужно было написать в `submission.ipynb`, не меняя сигнатуры функций и классов, потому что автотесты завязаны на ожидаемые имена и структуру ноутбука.

Каталог содержит 10 товаров: наушники, earbuds, клавиатуры, мыши и e-reader. Для работы с каталогом доступны два основных инструмента:

- `search_products` - поиск товаров по текстовому запросу, категории, бренду, максимальной цене и сортировке;
- `add_to_cart` - добавление выбранного товара в корзину.

Задание состояло из трех частей:

1. Реализовать shopping agent с tool calling и ReAct-циклом.
2. Добавить агенту долговременную и краткосрочную память.
3. Построить multi-agent систему из нескольких специализированных агентов и координатора.

## Файлы

- `task.pdf` - постановка финального задания.
- `submission.ipynb` - ноутбук с реализацией решения и открытыми проверками.
- `_demo_profile_2a.json`, `_demo_profile_2b.json` - демонстрационные JSON-профили для проверки memory agent.

## Используемая модель

В ноутбуке используется LangChain-совместимый chat model client:

- `langchain_openai.ChatOpenAI`;
- endpoint Yandex Cloud: `https://ai.api.cloud.yandex.net/v1`;
- модель: `gpt-oss-20b/latest`;
- температура: `0`.

Для запуска нужно заполнить переменные окружения:

```python
os.environ["YANDEX_CLOUD_API_KEY"] = "<api-key>"
os.environ["YANDEX_CLOUD_FOLDER"] = "<folder-id>"
```

В ноутбуке также оставлен альтернативный закомментированный вариант подключения через `ChatOllama`.

## Решение

### 1. Tool-Calling Agent

В первой части реализован ReAct-агент `run_shopping_agent`.

Что сделано:

- добавлены docstring-описания к функциям `search_products` и `add_to_cart`;
- через `convert_to_openai_tool` собрана схема инструментов `SHOP_TOOLS_SCHEMA`;
- задан системный промпт `REACT_SYSTEM_PROMPT`, который заставляет модель сначала искать товары, а затем при необходимости добавлять их в корзину;
- реализован цикл до 5 шагов:
  - отправка истории сообщений в LLM;
  - обработка `tool_calls`;
  - вызов `tools.search_products` или `tools.add_to_cart`;
  - запись результата в `ToolTracer`;
  - добавление `ToolMessage` обратно в историю;
  - возврат финального текстового ответа, когда инструмент больше не нужен.

Открытые проверки подтверждают, что агент:

- ищет беспроводные наушники дешевле 150 долларов;
- находит беспроводную мышь дешевле 120 долларов и добавляет самую дешевую в корзину;
- ищет беспроводную клавиатуру с лучшим рейтингом и добавляет ее в корзину.

### 2. Memory Agent

Во второй части реализован агент `run_memory_agent`, который расширяет shopping agent памятью.

Долговременная память:

- профиль пользователя хранится в JSON-файле;
- `load_profile` читает профиль;
- `save_profile` сохраняет профиль;
- `update_profile` обновляет отдельное поле профиля;
- в профиль сохраняются стабильные предпочтения: имя, бренд, бюджет, цвет, категория и похожие пользовательские данные.

Краткосрочная память:

- между вызовами передается список `history`;
- в историю сохраняются `HumanMessage`, `AIMessage` и `ToolMessage`;
- благодаря этому агент может обработать follow-up запрос вроде "Add the first one found to cart".

Для memory agent собрана расширенная схема инструментов `SHOP_TOOLS_SCHEMA_WITH_MEMORY`, куда входят:

- `search_products`;
- `add_to_cart`;
- `update_profile`.

Открытые проверки подтверждают, что агент:

- сохраняет предпочтения пользователя в профиль;
- в новой сессии читает ранее сохраненные имя и бюджет;
- помнит результаты прошлого поиска в рамках короткой истории и добавляет первый найденный товар в корзину.

### 3. Multi-Agent System

В третьей части реализована цепочка агентов, работающих через общий `AgentContext`.

Состав системы:

- `RetrieverAgent` - извлекает параметры запроса и вызывает `search_products`;
- `ProsAgent` - генерирует преимущества для каждого найденного товара;
- `ConsAgent` - генерирует недостатки для каждого найденного товара;
- `RankerAgent` - выбирает лучший товар детерминированной логикой;
- `CoordinatorAgent` - запускает цепочку, собирает trace, при явном запросе пользователя добавляет лучший товар в корзину.

`RetrieverAgent` использует только инструмент поиска. Дополнительно в нем есть fallback-извлечение `max_price` из текста запроса регулярными выражениями, чтобы бюджет не терялся, если модель не передала его в аргументах tool call.

`ProsAgent` и `ConsAgent` работают без инструментов. Они получают JSON со списком кандидатов и возвращают JSON вида:

```json
{
  "product_id": "pros or cons text"
}
```

`RankerAgent` не использует LLM. Он:

- фильтрует кандидатов по `ctx.max_price`, если бюджет задан;
- выбирает товар с максимальным рейтингом;
- при равном рейтинге выбирает более дешевый товар;
- записывает действие `rank_candidates` в tracer.

`CoordinatorAgent`:

- последовательно делегирует работу агентам;
- пишет trace с ключами `delegate_retriever`, `delegate_pros`, `delegate_cons`, `delegate_ranker`;
- вызывает добавление в корзину только если пользователь явно просит купить или добавить товар;
- возвращает `AgentResult` с финальным ответом, trace и заполненным контекстом.

Финальный ответ координатора содержит название выбранного товара, цену, рейтинг, плюсы и минусы. Если товар был добавлен в корзину, ответ дополняется информацией о результате добавления.

Открытые проверки подтверждают, что multi-agent система:

- проходит полный цикл поиска, анализа, ранжирования и добавления мыши в корзину;
- при обычном поиске клавиатуры не добавляет товар в корзину;
- корректно разрешает tie-break по цене при равном рейтинге;
- соблюдает ограничение `max_price` при ранжировании.

## Как запустить

1. Открыть `submission.ipynb`.
2. Заполнить `YANDEX_CLOUD_API_KEY` и `YANDEX_CLOUD_FOLDER`.
3. Запустить ячейки сверху вниз:
   - подключение модели;
   - template cell;
   - ячейку с решением;
   - открытые проверки для задач 1, 2 и 3.
4. Убедиться, что проверки выводят `OK`.

В результате получился набор из трех агентных решений для shopping-сценария:

- одиночный ReAct-агент с tool calling;
